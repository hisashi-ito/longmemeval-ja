あなたは、英語の長期記憶ベンチマーク LongMemEval の 1 問を、日本で暮らす人の日本語の会話に作り直す担当です。

入力は JSON で、1 つの質問、その答え、質問した日付、答えの根拠になる会話(日付つき、1〜数本)です。会話は利用者(user)とアシスタント(assistant)のやり取りで、答えの根拠を含む発言には has_answer が true で付いています。

## 作り直しの決まり

1. 利用者は日本に住む日本人として、自然なくだけた日本語で話す。アシスタントは丁寧な日本語で答える。英語の直訳の調子にしない
2. 米国に固有のものは、日本で暮らす人が実際に話すものに置き換える
   - お金はドルを円にする。金額は日本の相場で自然な額にする(1 ドル = 100 円の機械的な換算にしない)
   - マイル、ポンド、華氏、ガロンなどは、キロメートル、キログラム、摂氏、リットルにする
   - 店、地名、学校、祝日、行事、食べ物、制度(保険、税、住宅ローンなど)は、日本の暮らしで自然なものにする
   - 置き換えは、全部の会話と質問と答えで同じものにそろえる
3. 答えが会話から導けることを、作り直したあとも必ず保つ
   - 数(回数、金額、年数、距離など)を変えたら、足し算や引き算で出る答えも計算し直して、答えをそれに合わせる
   - 日付と曜日は変えない。会話の日付(date)と質問の日付(question_date)はそのまま写す。出来事の前後関係も変えない
   - 答えに要る事実を落とさない。答えに関係しない言い回しは自由に整えてよい
4. 答えない判断の問題(答えが「その情報はない」の趣旨のもの)は、質問で聞かれている事柄が、作り直した会話の中にも出てこないように保つ
5. 会話の形を保つ。会話の本数と順番、各会話の発言の数と順番、role、has_answer の付いた位置を変えない
6. アシスタントの長い返事は、日本語として自然な長さに整えてよい。ただし、答えに関わる発言(has_answer が true の発言と、質問がアシスタントの発言を聞いている場合のその発言)の中身は落とさない
7. 置き換えた固有名詞は、質問と答えにも同じ名前で書く。置き換えのせいで質問があいまいにならないようにする(例: 雑誌の名前を置き換えたら、質問でも「週刊誌」とぼかさず、その雑誌の名前で聞く。会話に同じ種類のものが複数出るときは特に注意する)
8. 元の会話にあった値(金額、回数、時刻など)は伏せずに、置き換えたうえで残す
9. 出力の文章に、作り直しの途中の考えや迷いを書かない(「○○風ではなく」「△△に置き換えた」のような言葉を、会話、質問、答えに入れない)。置き換えの説明は replacements にだけ書く
10. 本、映画、ドラマ、音楽、ゲームなどの作品は、海外のものでも日本の作品に置き換えない(日本の利用者も海外の作品を読み、観る)。日本語版の題名が広く知られていればそれを使い、無ければ原題のまま書く。作品にまつわる読書会や同好会の名前は、日本語にしてよい

## 出力

次の形の JSON だけを出力する。前置きや説明、コードの囲みは付けない。

{
  "question": "日本語の質問",
  "answer": "日本語の答え",
  "question_date": "入力と同じ",
  "sessions": [
    {
      "session_id": "入力と同じ",
      "date": "入力と同じ",
      "turns": [
        {"role": "user", "content": "日本語の発言", "has_answer": true}
      ]
    }
  ],
  "replacements": [
    {"from": "元の語や値", "to": "置き換えた語や値", "reason": "置き換えの理由(短く)"}
  ],
  "answer_check": "作り直した会話のどの発言から、どう答えが導けるかを 1〜3 文で"
}

has_answer は、入力で true だった発言にだけ付け、それ以外は省く。
